# 🏃 runbet

runbet은 러닝 챌린지를 만들고 참가자와 함께 달린 거리를 기록하는 서비스입니다. 참가자는 챌린지에 참가비를 내고, 종료 후 누적 거리 순위와 참가비 분배 결과를 확인할 수 있습니다.

현재는 데모 사용자와 `json-server`를 사용하는 로컬 프로젝트입니다.

## 로컬 실행

의존성을 설치한 뒤, 터미널 두 개에서 각각 실행합니다.

```bash
npm install
```

```bash
# 터미널 1: Mock REST API (http://localhost:9999)
npm run server
```

```bash
# 터미널 2: Next.js (http://localhost:3000)
npm run dev
```

## 1. 프로젝트 기본 정보

- **프로젝트명**: runbet
- **만들 서비스 한 줄 소개**: 러닝 챌린지를 생성하고 참가자별 누적 거리를 기록해 종료 후 참가비 분배 결과를 확인합니다.
- **이 서비스를 사용할 사람**: 러닝에 동기부여가 필요한 사람들

## 2. 구현한 기능

| 기능              | 구현 내용                                                                                                                      |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 챌린지 생성       | 제목, 기간, 최대 참가 인원, 참가비, 설명을 입력해 챌린지를 생성합니다. 생성자는 자동 참가하며 참가비가 잔액에서 차감됩니다.    |
| 초대 및 참가      | 초대 링크로 참가 화면에 이동해 데모 사용자를 선택하고 참가할 수 있습니다. 시작 전이며 정원이 남아 있고 잔액이 충분해야 합니다. |
| 러닝 기록         | 참가자는 챌린지 기간 중 날짜, 거리, 운동 시간, 메모를 기록할 수 있습니다. 저장된 기록은 참가자의 누적 거리에 반영됩니다.       |
| 진행 현황 및 결과 | 참가자, 기록 달력, 주간 기록을 조회하고, 종료된 챌린지의 누적 거리 순위와 참가비 분배 결과를 확인할 수 있습니다.               |
| 챌린지 조회       | 챌린지 목록과 참여한 챌린지 내역을 조회할 수 있습니다.                                                                         |

## 3. 화면 구성

| 화면   | 보여줄 내용                                                     | 사용자가 할 수 있는 일                                                          |
| ------ | --------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 화면 1 | 챌린지 목록, 챌린지 제목, 기간, 상태, 참가자 수                 | 챌린지 목록을 확인하고 챌린지 상세 화면으로 이동할 수 있다.                     |
| 화면 2 | 챌린지 생성 폼, 제목, 기간, 대결비, 참가자 정보                 | 챌린지를 생성할 수 있다.                                                        |
| 화면 3 | 챌린지 상세 정보, 참가자별 누적 거리, 전체 거리, 예상 분배 금액 | 자신의 달린 거리를 입력하고 참가자별 기록 및 대결비 분배 결과를 확인할 수 있다. |

**와이어프레임 첨부:** 손그림이나 간단한 화면 그림을 아래에 넣거나 별도 파일로 제출합니다.

## 4. 데이터 구조

데이터는 `db.json`에 저장합니다. 챌린지 참가자 배열에는 각 참가자의 누적 거리와 러닝 기록이 포함됩니다.

### 챌린지

| 필드명                 | 자료형 | 의미                |
| ---------------------- | ------ | ------------------- |
| `id`                   | 문자열 | 챌린지 식별자       |
| `title`                | 문자열 | 챌린지 제목         |
| `startDate`, `endDate` | 문자열 | 시작 및 종료 일시   |
| `maxParticipants`      | 숫자   | 최대 참가 인원      |
| `entryFee`             | 숫자   | 참가자 1인당 참가비 |
| `description`          | 문자열 | 챌린지 설명         |
| `coverImage`           | 문자열 | 대표 이미지 경로    |
| `participants`         | 배열   | 참가자 정보 목록    |

참가자 객체는 `userId`, `name`, `avatarIndex`, `joinedAt`, `paidAmount`, `distance`, `records`를 저장합니다. `records`의 각 항목은 `id`, `date`, `distance`와 선택 입력인 `durationSeconds`, `memo`로 구성됩니다. 참가자의 `distance`는 기록의 누적 거리입니다.

### 사용자

사용자 객체는 `id`, `name`, `avatarIndex`, `balance`를 저장하며 `balance`는 참가비 차감에 사용하는 데모 머니 잔액입니다.

**`db.json` 구조 예시:**

```
{
  "challenges": [
    {
      "id": "challenge-id",
      "title": "주말 러닝 챌린지",
      "startDate": "2026-10-01T09:00",
      "endDate": "2026-10-07T23:00",
      "maxParticipants": 4,
      "entryFee": 10000,
      "description": "일주일 러닝 챌린지",
      "coverImage": "/images/running-sunset.png",
      "participants": [
        {
          "userId": "demo-user-1",
          "name": "나",
          "avatarIndex": 0,
          "joinedAt": "2026-10-01T00:00:00.000Z",
          "paidAmount": 10000,
          "distance": 10,
          "records": [
            { "id": "record-1", "date": "2026-10-02", "distance": 10, "durationSeconds": 3600, "memo": "아침 러닝" }
          ]
        }
      ]
    }
  ],
  "users": [
    { "id": "demo-user-1", "name": "나", "avatarIndex": 0, "balance": 100000 }
  ]
}
```

## 5. API

Axios 인스턴스는 `NEXT_PUBLIC_API_BASE_URL`을 사용하며, 값이 없으면 `http://localhost:9999`에 요청합니다.

| 기능                     | 요청 방식 및 경로                           | 사용 데이터                                                                                                  |
| ------------------------ | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 챌린지 목록 조회         | `GET /challenges`                           | 챌린지 배열을 조회합니다.                                                                                    |
| 챌린지 상세 조회         | `GET /challenges/:id`                       | 챌린지 한 건을 조회합니다.                                                                                   |
| 챌린지 생성              | `POST /challenges`, `PATCH /users/:id`      | 챌린지와 생성자 참가 정보를 저장하고 생성자 잔액을 차감합니다. 잔액 차감 실패 시 생성된 챌린지를 삭제합니다. |
| 챌린지 참가              | `PATCH /challenges/:id`, `PATCH /users/:id` | 참가자 목록을 갱신하고 참가자 잔액을 차감합니다. 잔액 차감 실패 시 참가자 목록을 복구합니다.                 |
| 러닝 기록 등록           | `PATCH /challenges/:id`                     | 참가자의 기록 목록 및 누적 거리를 갱신합니다.                                                                |
| 사용자 조회 및 잔액 확인 | `GET /users`, `GET /users/:id`              | 참가 화면의 사용자 목록과 데모 사용자 잔액을 조회합니다.                                                     |

조회 중에는 로딩 상태를 표시하며 조회 실패 시 오류 안내를 제공합니다. 목록과 기록에 데이터가 없으면 빈 상태 안내를 표시하고, 생성·참가·기록 저장 중에는 진행 상태와 오류 메시지를 표시합니다.

## 6. 상태 관리

| 상태                               | 사용 위치                     | 관리 방법                                                |
| ---------------------------------- | ----------------------------- | -------------------------------------------------------- |
| 챌린지 생성 폼 입력 및 검증 메시지 | 생성 화면                     | `useState`                                               |
| 러닝 기록 입력값 및 날짜           | 기록 등록 화면                | `useState`                                               |
| 참가할 사용자 선택                 | 참가 화면                     | `useState`                                               |
| 달력의 월 및 선택 날짜             | 기록 달력                     | `useState`                                               |
| 초대 링크 복사 상태                | 초대 화면                     | `useState`                                               |
| 챌린지와 사용자 서버 데이터        | 목록, 상세, 참가 및 결과 화면 | TanStack Query `useQuery`; 데이터 변경 후 관련 캐시 갱신 |

- **Zustand**: 사용하지 않습니다. 화면별 입력 상태는 `useState`, API 서버 상태는 TanStack Query로 관리합니다.
- **TanStack Query**: 챌린지와 사용자 조회에 `useQuery`, 챌린지 생성·참가 및 기록 등록에 `useMutation`을 사용합니다.
- **새로고침 후 유지되는 데이터**: 챌린지, 사용자 잔액, 참가자와 러닝 기록은 `db.json`에 저장됩니다.
